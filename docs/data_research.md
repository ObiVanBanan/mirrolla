## 5. Сопоставление с 1С API (из `tz.md`)

| 1С поле | Ozon | WB | Примечание |
|----------|------|-----|------------|
| `code` | `Артикул` | `Артикул продавца` | Прямой ключ (`ЦБ-00050105`) |

| `articleOzon` | `SKU` | — | SKU Ozon (int) |
| `articleWb` | — | `Артикул WB` | Артикул WB (int) |
| `gtin` | — | `Штрихкод` | GTIN/EAN-13 |

### Чего НЕ хватает в данных:
- **Цена продажи** — ни в Ozon, ни в WB нет колонки цены. Оценить изменение цены нельзя.
- **Выручка** — нет колонки суммы/выручки. Только количество заказов.
- **Себестоимость** — отсутствует.
- **Категория товара** — нет явной категории. Можно выводить из названия.
- **Исторические остатки** — WB не содержит остатков. Ozon тоже. Остатки только из 1С (`ProductBalances`).
- **Возвраты** — нет отдельной колонки возвратов. `Статус получения = Отменен` в Ozon — ближайшее.
- **Цены конкурентов** — отсутствуют.

### Что ЕСТЬ и можно использовать:
- **Количество заказов** по товару по дням (Ozon) → тренд продаж
- **Оценки и отзывы** (обе платформы) → sentiment, негативные отзывы
- **Штрихкод** (WB) → связь с 1С через `gtin`
- **Бренд** (WB) → группировка по брендам
- **Объём товара** (WB `Цвет`) → различение SKU внутри товара

## 7. Особенности и подводные камни

1. **Ozon данные — это НЕ продажи.** Это заказы + отзывы. Нет цены, нет выручки. Можно считать количество заказов как proxy для продаж.
2. **WB данные — это ТОЛЬКО отзывы.** Нет данных о продажах/заказах WB вообще.
3. **80% отзывов без текста** (обе платформы) — только оценка (1–5 звёзд).
4. **Оценки сильно смещены в 5★** (Ozon 91.7%, WB 86.1%). Негативных отзывов мало: 1–2★ = ~1%.
5. **Нет цен и выручки** — нельзя напрямую ответить на «изменение цены» из данных. Только через 1С (если там есть) или если придут доп. данные.
6. **Нет категорий товаров** — можно вывести из названия (шампунь, масло, капсулы, крем и т.д.).
7. **WB `Цвет` — это объём/формат**, не цвет. WB `Размер` — мусор.
8. **Бренд и Регион** — требуют нормализации регистра.
9. **Штрихкод** в WB — int64. При конвертации в str нужно дополнять до 13 цифр (EAN-13), иначе потеряются ведущие нули.
10. **5 артикулов WB с суффиксом `+`** — проверить с 1С, возможно это комплекты.
11. **Файлы Ozon overlapping по датам**: файл 1 заканчивается 16.04, файл 2 начинается 16.04 — дубли на границе? Проверить при объединении (по `Номер заказа` + `Артикул`).
