## Решения

### R1. Цены и ценообразование — вопрос №6 не реализуется

**Вопрос из ТЗ:** «Какие товары требуют изменения цены?»

**Статус:** ❌ Не реализуется в MVP. Отсутствуют исходные данные.

**Обоснование:**
- В Ozon-выгрузках нет колонки цены продажи (только заказы и оценки)
- В WB-выгрузке только отзывы, данных о продажах/ценах нет
- В 1С API (`ProductSales`) возвращается только `quantity` (количество), без суммы/цены
- Цен конкурентов, себестоимости, комиссий маркетплейсов — нет ни в одном источнике

**Что можем сделать вместо этого:**
- Косвенный сигнал: продажи упали + остаток есть + негатив не вырос → «рассмотреть снижение цены»
- Это не «изменение цены», а догадка. Указываем в README и UI как ограничение.

**Что нужно для полноценной реализации:**
- Выгрузка цен продажи из WB/Ozon (отдельным API или отчётом)
- Цены конкурентов
- Себестоимость из 1С
- Комиссии маркетплейсов

### R2. «Рынок» = категория товаров (productType) внутри данных Mirrolla

**Статус:** ✅ Реализовано

**Обоснование:**
- В данных нет статистики рынка WB/Ozon
- `ProductInformation` из 1С отдаёт `productType`: 4 категории (Косметика 1886, БАД 1760, Прочее 197, Растительные масла 11)
- Реализовано: `category_growth_by_type()` — рост по категориям, `faster_than_market()` — товар vs своя категория
- В интерфейсе и README указываем: «рынок = категория внутри портфеля Mirrolla»

### R3. Продажи WB — недоступны

**Статус:** ❌ Нет данных

**Обоснование:**

### R7. Комбо-анализ «Почему упали продажи» — 5 гипотез

**Статус:** ✅ Реализовано

**Реализация:** `helpers/sales.analyze_decline()` — по одному товару проверяет:
- H1 — дефицит остатков (stockout): остаток = 0 или < 20 → подтверждено
- H2 — рост негативных отзывов: WB + Ozon отдельно
- H3 — падение категории: `productType` из 1С
- H4 — падение портфеля: общий тренд
- H5 — изменение цены: ❌ нет данных (см. R1)

**Ограничение:** если ни одна гипотеза не подтверждена — вероятная причина «не найдена» (цена, реклама, сезонность — данных нет).

**Статус:** ✅ Реализовано

### R9. LLM и execution — OpenAI gpt-4o + Code Interpreter

**Статус:** ✅ Решено (День 2)

**Решение:**
- **Reasoning** (план, гипотезы, ответ): OpenAI `gpt-4o`
- **Code execution** (sandbox): OpenAI Code Interpreter (hosted)
- **Оркестрация**: LangGraph (planner → HITL → executor → responder)
- **UI**: Streamlit (локально на Windows)
- **1С**: через VPN (только с компа разработчика)

**Почему не Ollama:**
- Code Interpreter — hosted tool OpenAI, работает только с OpenAI моделями
- Готовый sandbox не нужно настраивать
- gpt-4o лучше пишет Python код

**Почему не function calling (Вариант B):**
- Пользователь выбрал гибкость: агент пишет Python код сам
- При изменении данных/добавлении гипотез — не нужно обновлять helpers
- Code Interpreter сам исправляет ошибки в коде
