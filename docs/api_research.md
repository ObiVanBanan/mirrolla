## 3. Функция `ProductInformation` — каталог товаров

### Запрос

```bash
POST http://192.168.201.250/Sklad_Server/hs/WebAssistant/ProductInformation
Content-Type: application/json
Body: []   # пустой массив = всё дерево номенклатуры
```

### Поведение

| Тело | Результат |
|------|-----------|
| `[]` (пустой массив) | ✅ **Полное дерево** всей номенклатуры. Ответ: **7.3 MB**, таймаут 60 сек. |
| `["ФР-00000025"]` (любой код) | ⚠️ Возвращает **только корневую группу** (`ФР-00000002`, `isGroup: true`, `children: []`). Код игнорируется. |
| `["380341307"]` (Ozon SKU) | ⚠️ То же — корень дерева, игнорирует. |
| `["18546638"]` (WB article) | ⚠️ То же — корень дерева, игнорирует. |

### Особенность

Фильтр по кодам **не работает**. С любым непустым массивом возвращается только корень дерева с пустым `children: []`. Единственный способ получить каталог — передать `[]` и выгрузить всё дерево (7.3 MB), затем распарсить и flatten на стороне приложения.

## 4. Функция `ProductBalances` — остатки

### Запрос

```bash
POST http://192.168.201.250/Sklad_Server/hs/WebAssistant/ProductBalances
Content-Type: application/json
Body: []   # пустой массив = все товары
```

### Поведение

| Тело | Результат |
|------|-----------|
| `[]` (пустой массив) | **Полный список всех товаров с остатками**. Плоский массив. |
| `["ФР-00000003"]` (любой код) | **`[]` — пустой ответ!** Фильтр по кодам не работает. |
| `{"codes": ["ФР-00000003"]}` (объект) | **Ошибка 1С**: `Значение не является значением объектного типа (Количество)` |

### ⚠️ Фильтр по кодам не работает

API игнорирует переданные коды. С конкретным кодом возвращает `[]`, с пустым массивом — весь список. Нужно выгружать всё и фильтровать на стороне приложения.

### Структура ответа

```json
[
  {
    "code": "ФР-00000003",
    "name": "Жир алтайского барсука обогащенный масляным экстрактом шалфея серии «Mirrolla»® 200 мл",
    "balance": 324
  },
  {
    "code": "ФР-00000004",
    "name": "АЕвит «Мирролла»® /масляный р-р вит. А и Е/ с природными витаминами №30 инд.упак.",
    "balance": 0
  }
]
```

### Поля ответа `ProductBalances`

| Поле | Тип | Описание |
|------|-----|----------|
| `code` | str | Код номенклатуры |
| `name` | str | Наименование |
| `balance` | int | Остаток (количество) |

**Остаток — текущий snapshot**, не исторический. Без даты/времени.

## 5. Функция `ProductSales` — продажи

### Запрос

```bash
POST http://192.168.201.250/Sklad_Server/hs/WebAssistant/ProductSales
Content-Type: application/json
Body: {
  "dateStart": "20260601",
  "dateEnd": "20260602",
  "codes": ["ФР-00000003"]
}
```

### Формат даты

**⚠️ ГГГГММДД** — строка 8 цифр без разделителей. Не ISO (`2026-06-01`), не DD.MM.YYYY.

Неправильный формат → ошибка:
```
Ошибка: Некорректный формат даты. Ожидается ГГГГММДД
```

### Поведение

| Тело | Результат |
|------|-----------|
| `{"dateStart":"20260601","dateEnd":"20260602","codes":[]}` | **Полный список всех товаров** с `quantity` за период |
| `{"dateStart":"20260601","dateEnd":"20260602","codes":["ФР-00000003"]}` | `[]` — пустой (фильтр не работает?) |
| `{"dateStart":"20260317","dateEnd":"20260318","codes":[]}` | Список всех товаров, все `quantity: 0` |

### Структура ответа

```json
[
  {
    "code": "ФР-00000003",
    "name": "Жир алтайского барсука...200 мл",
    "quantity": 0
  }
]
```

### Поля ответа `ProductSales`

| Поле | Тип | Описание |
|------|-----|----------|
| `code` | str | Код номенклатуры |
| `name` | str | Наименование |
| `quantity` | int | Количество продаж за период |

**Продажи агрегированы за весь период** — не по дням. `dateStart` и `dateEnd` задают интервал, результат — сумма за период.

| `ProductInformation` с пустым массивом → дерево | ✅ Подтверждено, но ответ огромный (таймаут 15 сек) |

| Поля `articleOzon`, `articleWb` в каталоге | ⚠️ **Часто пустые** — не все товары имеют артикулы WB/Ozon в 1С |

## 8. Стратегия работы с API для MVP

### ProductInformation
- Выгрузить всё дерево один раз (увеличить таймаут до 60+ сек)
- Распарсить дерево: `flatten` — оставить только `isGroup: false`
- Кэшировать локально (Parquet/JSON)

### ProductBalances
- Выгрузить всё (пустой массив → полный список)
- Сохранить как snapshot с timestamp

### ProductSales
- Вызвать с `dateStart`/`dateEnd` в формате `ГГГГММДД`
- Передать `codes: []` для всех товаров
- Агрегация за период — для дневных данных вызывать по 1 дню

### Фильтрация по кодам
- **Не работает на стороне API** — делать на стороне приложения после выгрузки

## 9. Связь с данными выгрузок (Ozon/WB)

| 1С поле | Ozon | WB | Покрытие в 1С |
|---------|------|-----|---------------|
| `code` | `Артикул` | `Артикул продавца` | ✅ 3 854 товара — **главный ключ** |
| `name` | `Название товара` | — (выводится из бренда) | ✅ 100% |
| `gtin` | — | `Штрихкод` | ✅ 99% в 1С, но WB `Штрихкод` = int → нужно в str (13 цифр) |
| `articleOzon` | `SKU` | — | ❌ **11%** в 1С — бесполезно для маппинга |
| `articleWb` | — | `Артикул WB` | ❌ **13%** в 1С — бесполезно для маппинга |
| `productType` | — | — | ✅ 100% — категория товара (Косметика, БАД и т.д.) |
| `brand` | — | `Бренд` | ⚠️ 20% в 1С, но WB заполнен лучше |
| `releaseForm` | — | `Цвет` (объём) | ⚠️ Объём/формат |

### Ключевой вывод по маппингу

**`articleOzon` и `articleWb` в 1С заполнены только у 11–13% товаров** — использовать их для сопоставления с выгрузками Ozon/WB **нельзя**.

Единственный надёжный ключ: **`code` (1С) ↔ `Артикул` (Ozon) / `Артикул продавца` (WB)** — формат `ЦБ-XXXXXXXX`, `ФР-XXXXXXXX`.

Дополнительный ключ: **`gtin` (1С, 99%) ↔ `Штрихкод` (WB)** — но в WB это int, нужно конвертировать в str и дополнять до 13 цифр (EAN-13).
